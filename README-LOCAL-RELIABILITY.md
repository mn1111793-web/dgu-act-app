# Локальный этап надёжности (исходники, без APK)

База: `bf68102710cad2cc2629326814338e01a337a409`.
Ветка: `feature/dgu-local-reliability-2026-10-23`.

Изменения не устанавливались и не выполнялись на планшете. ApplicationId, SDK,
versionCode/versionName и настройки подписи не меняются. APK не является копией заявок.
Нужны отдельные разрешения на сборку и затем на установку; разные ключи прежних APK
по-прежнему исключают обещание обычного обновления установленного приложения.

## Поведение и хранение

* `files/local_snapshot_v1.json`: один JSON schemaVersion=1, заявки, акты, верхняя граница
  счётчика, резерв номера новой заявки и черновики. AtomicFile + явный fsync перед finishWrite. Отказ до finishWrite оставляет прежнюю базу;
  после входа в finishWrite результат может быть неопределённым: старые ИЛИ новые байты.
  В этой фазе failWrite не вызывается и возврат старого снимка не обещается. UI не объявляет
  успех, блокирует новые операции до перечитывания; повтор использует прежние ID. Повторное сохранение того же ID
  заменяет запись, не добавляет дубликат. Уникальные ID не зависят от бизнес-номера.
* Legacy `shared_prefs/saved_acts.xml` / `saved_requests.xml` читаются напрямую и строго;
  повреждение, незавершённый `.bak`, неизвестная версия или разорванная связь блокируют
  запись. Чтение не сохраняет «восстановленные» заявки. При отсутствии requests JSON
  существующие акты могут дать представление заявок в памяти. Первая запись (включая автосохранение открытой формы) создаёт
  новый снимок; исходные preferences не удаляются/не меняются. Перенос планшета не выполняется.
* Черновик привязан к requestId/actId/type. Именованные saveable-поля, списки фото,
  незавершённые и подтверждённые подписи/чек-листы сериализуются в типизированный JSON.
  Автосохранение отслеживает изменения Compose; перед «Назад», picker и камерой выполняется
  явная синхронная запись; ON_STOP тоже сохраняет. Ошибка видна, выход по «Назад» блокируется.
  Принудительное выключение в момент записи и аппаратный отказ не дают абсолютной гарантии.
* Черновик можно сохранить без подписи и заполнить позже. Каждая заявка содержит ровно
  один equipmentId; act.requestId/equipmentId проверяются совместно. Поля заказчика и конкретной
  единицы наследуются из заявки. Изменение общей карточки обновляет только неподписанные акты.
  Заполненные физические реквизиты изменяются только после явного подтверждения исправления
  той же единицы (диалог, затем повторное нажатие «Сохранить»). ID заявки/единицы сохраняются,
  неподписанные акты обновляются, signed-снимки неизменны. Пустые поля можно дополнить.
  Для другой физической единицы нужна новая заявка. Опечатка serial сама по себе новой заявки не требует.
* Редактирование акта с любой подписью создаёт новый actId, revision+1 и supersedesId,
  без подписей; исходная версия неизменяема и не удаляется обычными кнопками. Изменение
  содержимого формы после подтверждения подписи сбрасывает подписи с сообщением.
  Рисунок подписи не объявляется юридически равным собственноручной или ПЭП.
* Фото: постоянные оригиналы в `files/act_photos/request_ID/equipment_UUID/act_ID/`.
  Повторная камера и multi-picker; импорт через staging, fsync, rename. Отмена, редактирование,
  удаление записи не удаляют оригиналы или прежние PDF автоматически. Это намеренная
  консервативная политика: возможны неиспользуемые файлы и рост занимаемого места.
* Список сортируется по неизменному createdAtMillis и ID; legacy dd.MM.yyyy разбирается строго.
  Дата заявки, дата акта и время фактического создания не смешиваются. Отдельной юридической
  нумерации актов нет: тип + номер заявки + техническая версия.
* PDF A4: неизменённые юридические тексты, ДГУ Ямал, дата документа, заказчик, оборудование,
  таблицы с переносами строк/страниц и повторными заголовками, все подписи. Фото на отдельных
  страницах, EXIF-ориентация, декодирование с ограничением размера; отсутствие оригинала — ошибка.
  PDF сохраняется под уникальным actId/version/type/UUID. SAF предлагает выбор файла, печать
  использует системную службу; ни то, ни другое не является экспортом базы.

## Проверки без APK

`tools/source-check/run.py` компилирует и запускает только изолированные JVM-регрессии
на временных фикстурах. Нужны заранее доступные portable JDK17, Kotlin compiler 1.9.24,
библиотеки Compose/JSON/xpp3 в `DGU_CHECK_TOOLS` (по умолчанию workspace/.local-tools/dgu-check).
Скрипт сам ничего не скачивает, не вызывает Gradle, не создаёт APK и не использует ADB.
Android Context/AtomicFile/Xml заменены явно помеченными JVM-фикстурами: это проверка
логики production repository и codec, а не проверка Android AtomicFile или устройства.
Результаты пишутся в `tools/source-check/output/` (исключены из git).

Сборка Android ресурсов, DEX, R8, manifest merge, реальный lifecycle/камера/picker/SAF/печать
и визуальный PDF требуют следующего отдельно согласованного этапа. Gradle wrapper отсутствовал
в исходной базе; в этом этапе он не добавляется и Gradle не запускается.

Полный экспорт/импорт, Google, ИНН API, роли/backend/SMS не входят в этот этап.

`python3 tools/source-check/check_sources.py` отдельно проверяет все Kotlin-файлы
компилятором Kotlin 1.9.24 с Compose compiler 1.5.14, android.jar API35 и загруженными
AAR/JAR. Для R используется временная подстановка ID из исходников, поэтому успех этой
проверки не заменяет Android resource linking/полную сборку. Никаких APK-задач нет.

## Расширенное ревью владельца

- `python3 tools/source-check/run.py --all`: прежние регрессии и ReviewRegression с повреждёнными
  данными/отказами/двумя единицами и шестью актами, на искусственных JVM-данных.
- `python3 tools/source-check/run_aosp.py`: неизменённый алгоритм AtomicFile Android13 (кроме
  удалённых аннотаций) с host shims и production AtomicSnapshotWriter. Это не Android runtime
  и не файловая система планшета; см. tools/source-check/aosp/README.md и LICENSE.txt.
- Отдельный `.new` без базы/backup блокирует пустую инициализацию. Битый/неполный JSON,
  потерянные массивы, неверные типы/ссылки/счётчик блокируют запись. Backup проверяется до
  штатного восстановления; повреждённый или конфликтующий валидный `.bak` не затирает base.
  Штатный AtomicFile.openRead может переименовать проверенный .bak и убрать старый .new;
  это housekeeping атомарного файла, а не миграция/запись реконструированных заявок.
- Legacy одинаковые номера допускаются только уже существующими, если номер не меняется;
  связи остаются по ID. Ввод нового дубля номера отвергается.
- Формы сохраняются перед финальным save; UI списки меняются только после подтверждения.
  При ошибке введённые поля не отбрасываются. Нет безусловной гарантии от отказа носителя,
  питания, удаления файлов/приложения, неизвестного firmware или внешнего конкурирующего writer.

Рабочий планшет: этот source branch не установлен. Старый APK A не содержит новых функций.
Полный backup текущих private data пока не доказан; run-as отказал, облачный размер не
доказывает состав или восстановление. Не обновлять ради экспорта, не удалять приложение.
Современный UI, Room/единая БД, библиотека документов и серверные копии — только будущий
архитектурный план с отдельным согласованием, не реализация этого этапа.
