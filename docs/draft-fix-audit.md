## Исправленные отдельные дефекты

1. Whole-registry serialization с DefaultLazyKey до saveDraft — независимая DTO-модель/codec, явный capture всех полей; Compose registry остаётся Activity для scroll/focus/selection/launchers и не сериализуется на диск.
2. Имя компании без label не попадало в fallback из-за `.orEmpty()` до Elvis. Длинные ИНН/ОГРН выбирали короткую альтернативу. Парсер выделен для host tests, длинные варианты впереди с границей цифр.
3. PDF/DOCX и галерея читались в UI thread; вынесены в IO. Формат больше не определяется «любой пустой MIME = PDF», ошибки не маскируются как отсутствие текста.
4. Gallery busy выставлялся до успешного flush — после провала кнопка выглядела зависшей. Теперь только после успешного запуска, callback/finally сбрасывают.
5. После uncertain commit loaded=false не имел пути перечитывания. Добавлено явное действие; никаких автоматических retry с новым ID.
6. После исключения persist кэш lastSaved сбрасывается: если uncertain commit фактически записал новое, возврат пользователя к старому вводу всё равно требует записи. Иначе прежний cache мог ошибочно пропустить save.
7. SignaturePad pointerInput включал signature в key: каждый callback менял этот key и мог отменить coroutine до завершения штриха. Key теперь только editable/canvasSize, latest signature/callback через rememberUpdatedState; actual touch/много непрерывных штрихов ещё проверяет владелец.
8. Появившаяся при исправлении защита путей учитывает существующие фото сохранённой цепочки редакций, а pending camera всегда только новый/current act directory.

## Отсутствующие/планируемые функции, не объявлять багфиксом готовыми

OCR фото/сканов, DOC (старый Word), ИНН API, backend/auth/roles/approval/sync/Google Sheets, общий DB migration/backup, equipment→many requests, документы/сметы/каталоги/финансы не реализованы. Company card/nameplate UI отсутствуют в форме сдачи из ремонта (AcceptanceAct): там используются существующие реквизиты заявки; расширение UI этого сценария отдельно. PDF имя содержит TEST/type/actId/revision/UUID, а желаемый человекочитаемый номер/дата остаются будущим уточнением. Без реального PDF нельзя принять визуальную верстку/печать.

Хранилище пока AtomicFile snapshot, не полная БД. При очень больших формах синхронный flush может занимать время; UI-thread parsing/import убран, обещания мгновенного fsync нет. Нет аппаратного теста ENOSPC/power loss или фирменной прошивки. Print framework callbacks и физический принтер требуют ручного теста. Недоступный/повреждённый legacy draft не очищается; запись именно этой формы блокируется с сообщением, исходные байты остаются.
