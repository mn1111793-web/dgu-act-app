# План планшетного интерфейса — на согласование, НЕ реализован

Приоритет текущей сборки: сохранение и восстановление, затем действия. Этот документ не меняет UI и не подтверждает приёмку.

Палитра: основной тёмно-синий #123F56, фон #F2F5F7, белые поверхности, текст #172936; спокойные зелёные/оранжевые статусы с текстом/значком. Жёлтая гарантия отдельным признаком, не статусом. Тестовая плашка сохраняется во всех режимах.

Портрет: компактные горизонтальные карточки заявок с номером, заказчиком, датой, оборудованием/полным serial и текстом статуса; список по времени создания. Фильтры/поиск сверху, одна заметная кнопка новой заявки. Секции формы: заказчик → оборудование/шильдик → акт/чеклист → фото → подписи → проверка. Введённые значения живут вне секций и не зависят от их разворачивания. Статус сохранения с последним подтверждённым временем; ошибка записи остаётся видимой.

Альбом: список слева, карточка выбранной заявки справа; форма 2 колонки только для коротких полей, длинные тексты/чеклист/подписи на всю доступную ширину. Нет горизонтальной прокрутки всей страницы. Области касания минимум 48dp, реальная клавиатура и масштаб шрифта проверяются владельцем.

Навигация: единые внутренний и системный Назад через подтверждённое сохранение; при ошибке остаётся ввод и явное повторение записи. Выход из picker не очищает форму. Действия «Записать акт», «Сохранить PDF», «Поделиться», «Печать» различаются. Распознанные реквизиты сначала показываются с разницей старое/новое и отдельным подтверждением.

Будущие разделы: Заявки, Оборудование, Контрагенты, Документы, Техбиблиотека, Прайсы/сметы. Роли/сервер/синхронизация/финансы/оборудование→много обращений — отдельный этап; до реализации показывать их как план, не действующие элементы.

Согласовать: плотность карточки, порядок секций, размещение навигации в портрете/альбоме. Приложенный tablet-ui-mockups.html — статический эскиз для этого согласования, без рабочих кнопок/сети/данных клиентов.
